## Findings

### Medium

1. **`stasis://` URL commands run with no confirmation** (`Stasis/Services/StasisURLHandler.swift`). Any local app or web page that can open a URL can change the charge limit, start force discharge, or start calibration. Inputs are clamped, so the impact is battery behaviour rather than code execution. Not changed, since the scheme is a documented feature. Options: confirm state-changing commands the first time, or add an opt-in setting.
2. **`SMCKit` is tracked by branch (`main`)** in `stasis.xcodeproj/project.pbxproj`. `Package.resolved` pins a revision, so builds are reproducible, but a bare `swift package update` would pull unreviewed code into a project that is linked into a root helper. Consider pinning to a tag or revision.

### Low

3. **README says the repository is private** and gives a `gh release download` workaround. The repository is public.
4. **`SECURITY.md` points vulnerability reports at the upstream author's email address**, not this fork's maintainer.
5. **The helper's setting ranges differ from the app's.** `ChargingSettings.setSettings` accepts sailing limits 1–100 and heat limits 20–60, while the app and URL handler enforce 5–20 and 30–50. The helper is the safer side to tighten, but doing so changes behaviour, so it was left alone. Both are bounded.
6. **`Process` use** (`pmset`, `top`, `system_profiler`, `tccutil`, `sudo`) all pass fixed argument arrays with no user-controlled strings. No injection path found.

### Informational (checked, no issue)

- The privileged installer script builds every path through `shellQuoted` and verifies code signature hashes after copying.
- XPC connections are checked against the app's code-signing requirement, both by PID and on the connection itself.
- `manageMagsafeLED` rejects values that are not a `MagSafeLEDState`.
- SwiftPM pins: Defaults 9.0.6, Sparkle 2.9.2, swift-syntax 602.0.0, SMCKit (branch `main`).

## Fixed in this branch
